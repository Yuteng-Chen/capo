# Coordination protocol

在多 Worker、大仓库、跨模块、跨回合任务，或涉及 Worker 替换、暂停、恢复时读取本协议。共享快照仅在任务需要时建立。调用限制见 [宿主运行策略](runtime-policy.md)，证据字段见 [运行记录格式](record-format.md)。

## 共享上下文快照

在运行目录保存 `context.md`，只放下游任务共同需要的事实：

- 独立递增的 `context_revision` 与适用的 `requirement_version`。
- 工作区身份：仓库 commit、未提交变更摘要；无 Git 时记录相关文件摘要或观察时间。
- 每条事实的来源路径或链接、观察到的版本或摘要、定位锚点、影响的任务与验收项。
- 明确的失效条件，例如需求版本变化、来源文件或 commit 改变、接口约定变化、验收 oracle 更新。

Worker 优先读取快照，再按自己的任务补查。快照中的事实不扩大可写范围或授权。派工和回报都携带 `context_revision`。触发失效条件时保留旧版或变更记录，把受影响事实标为 stale，只刷新相关部分，递增版本。检查适用暂停后，把变化发给受影响的 Worker。命中暂停的通知先排队，其他通知照常投递。按记录格式逐项判断证据是否失效或可显式沿用。

## 按范围暂停与恢复

运行记录使用 `pauses` 集合，不以单一全局布尔值代替范围。每条记录含 `pause_id`、`scope`（整轮 run_id、task_id 或明确的操作对象及操作范围）、`control_revision`、用户原话、时间、Worker 实际处置和解除记录。新增或解除记录时递增控制版本，保留历史。

- 派工、send/followup、改派、自动唤醒、集成、验收和上下文恢复前，检查该动作的任务、对象及整轮范围。任一匹配暂停未解除就禁止推进该范围。整轮暂停覆盖所有任务，局部暂停互不替代。
- “A 暂停、B 继续”允许 B 的独立执行和验收；依赖 A 未完成产物的步骤等待，B 的其他步骤继续。仅用户明确指令能解除暂停，回调和状态变化不授权恢复。
- 立即冻结匹配范围，持久记录可写时先落盘。记录位置只读或写入失败时，用会话内记录维持冻结，立即继续停止操作并注明尚未持久化。若用户要求停编辑或停止在途工作，使用可用 interrupt/stop 并核实 Worker 及写入进程，分别记录请求已接受、实际已停止或未确认。停止不等待落盘、模型预算或空闲槽位。
- 停止指令、只读状态核查、记录需求与迟到回报始终允许。暂停期间先更新需求与证据失效，仅命中暂停范围的变更通知、执行和验收排队；其他范围继续。恢复后先读取最新版本再处理对应队列。
- 恢复须从用户指令和上下文唯一定位范围及要解除的暂停记录。只解除指定记录；重叠的其他暂停仍有效。对象不明时保持暂停，询问恢复对象，继续明确获准的独立工作。
- 恢复前检查剩余暂停、需求、上下文、分派版本、Worker、产物和证据。恢复不自动释放写域，也不跳过下节的交接检查。
- 局部暂停不自动暂停整个原生 goal；整轮暂停才按宿主规则同步相关 goal。不要自行创建 goal，恢复遵守宿主授权。
- 兼容旧记录：仅有全局 `control_state: paused` 时视为整轮暂停；带有明确范围的旧暂停按原范围转换。保留原始记录及转换说明，普通上下文重载不解除任何暂停。

## Worker 替换与写入交接

逻辑任务和操作对象不变时保留 `task_id`，首次分派的 `assignment_revision` 为 1，每次改派递增。记录旧、新 Worker ID、实际工作目录、可写范围及交接证据，派工和回报都携带分派版本。旧记录缺少分派版本时标为 legacy，仅在核对实际 Worker 与产物后建立新分派。

重新分配重叠写域（包括新建任务但继续改同一产物）前，Router 必须满足下列一种条件：

1. **已释放原写域：** 有证据确认旧 Worker 及其启动的写入进程已经停止；或者旧 Worker 明确交回，确认没有在途写入、后台写入进程或后续写入，并不再向该旧分派发送唤醒指令。仅失联、超时、一次文件摘要未变、Worker 空闲但写进程未知、工具接受 interrupt 请求，均不足以证明释放。记录实际观察及证据路径。
2. **隔离替补：** 无法证明停止时，在独立 worktree 或独立副本执行。逐项核对所有适用的真实路径、符号链接、硬链接、生成目录和共享输出目录；隔离的文件不能解析到旧目录或共享可写资源。生成目录、外部数据库/服务等副作用也必须独立，无法隔离的写操作保持阻塞。从已核对的稳定材料建立替补输入，不能把旧作者可能正在写的目录当作稳定快照。

无法满足任一条件时，仅阻塞受影响写域，独立任务继续。独立 worktree 是工作目录安排，不是阻止 Worker 越界的沙箱；若没有真实权限隔离，必须如实说明保障范围。

隔离替补完成后，必须按本节“已释放原写域”的完整条件重新确认目标写域已释放（包括旧 Worker 启动的写入进程），才可合入；只确认 Worker 轮次停止不够。释放前不把产物合入旧作者仍能写入的目标目录，也不宣布该目标已集成完成。合入前重新检查全部适用暂停及目标变化，只集成当前分派、当前需求的已核对产物，集成后重新验证。

旧 Worker 恢复通信时，通过停止控制告知其分派已被替代并要求停止或交回。旧分派迟到回报只记历史。需要再次使用旧 Worker 时，先通过暂停、写域、并发及预算检查，再显式创建新的分派版本。

## 精确续作与交回

用 `task_id` 和稳定的操作对象定位任务。`requirement_version` 随投递变化。逻辑任务、对象和验收仍兼容且当前 Worker 可寻址时，按其实际状态投递新版本。Worker 不可寻址而任务仍兼容时，保留 `task_id`，完成写域检查后改派。对象、交付物或验收要求不兼容时新建任务。

Worker 发现需要修改未授权对象、越过可写范围、改变跨模块约定或替用户决定含糊业务规则时：

1. 停止越界修改，保留已验证的范围内结果。
2. 回报 `blocked`，写明触发点、所需扩展、受影响验收项和证据。
3. 由 Router 决定扩充原任务、新建任务或请求用户决策，再更新需求与任务版本。

## 独立验收与集成

复核者使用原始要求、冻结验收项和必要原始材料形成独立结论。无法取得独立证据时保持 `unverified`。集成者检查最终 diff 并运行相关验证，按记录格式绑定最终产物证据。
