# Capo

主会话担任 Router，持续对接用户并组织 Worker。收到 Router 分派的会话以 Worker 身份执行，默认不再派工。使用当前环境真实提供的原生子代理工具。先读取适用的项目指令。用户目标和现有授权决定工作范围。

## 建立目标与记录

将用户原始要求整理为当前需求版本、交付物、约束和可检查的验收项。每项验收条件写明证据来源或实际验证方式。用户已有清晰标准时直接执行，涉及业务取舍的缺失信息才向用户询问。

多阶段任务在项目的 `work/capo/<run-id>/` 保存运行记录。用户指定输出位置时使用该位置。按 [运行记录格式](references/record-format.md) 记录任务身份、分派、消息、回报、验收、预算和控制历史。记录不可写时用会话内记录继续控制，注明持久化限制。落盘失败不得延迟停止。

恢复上下文时先读运行记录和真实产物，重新应用全部未解除的暂停范围。派工、续投、改派、集成和验收前均检查适用暂停。匹配任一未解除暂停即禁止该范围推进，无关任务继续。重复请求先查关联任务。单纯查询进度时只汇总已有状态和证据，可做只读状态核查。

任务涉及多个 Worker、大型仓库、跨模块改动或跨回合执行时，按 [协调协议](references/coordination-protocol.md) 建立带来源与失效条件的共享上下文快照。遇到 Worker 替换、暂停或恢复时也读取该协议。简单任务不额外创建共享包。

## 实际派工

本 Skill 明确要求对适合独立执行的工作使用子代理。首次调用前读取 [宿主能力、并发与模型预算](references/runtime-policy.md)。Router 统一派发及预留，不设固定 Worker 数量上限，按独立任务、依赖及宿主可用容量安排并发，遵守用户明确设定的限制。按实际宿主能力选择 `routine`、`complex` 或 `analyst`，默认高级研判预算为零。宿主不可用或无法满足预算时由 Router 串行执行并记录原因。Worker ID 取自真实调用结果或宿主核查证据。

派工包含任务 ID、`assignment_revision`、当前需求版本、适用的上下文版本、原始要求、对应验收项、必要输入、依赖、实际工作目录、可写范围、交付物和验证要求。要求 Worker 发现超出对象、授权或可写范围时停止扩写并交回 Router。Worker 自行调查和选择局部实现方式。多个 Worker 写入时分配不重叠的文件或独立 worktree。共享状态与合并由 Router 协调。

## 执行中的沟通与变更

主会话继续回答用户，Worker 保留各自任务上下文。需要向 Worker 请求状态时先检查宿主是否可能为其启动新轮次，并按运行策略处理。

收到影响结果的要求后，递增 `requirement_version`，保留原要求，写明新增、修改、取消的验收项。先记录变更与证据失效，再检查暂停范围。被暂停的变更排队，明确恢复后才投递。逻辑任务、操作对象和验收仍兼容时保留 `task_id`，按宿主状态和预算发送消息、续投或改派。替换 Worker 或重叠写域重分配须执行协调协议的写入交接检查。

分别记录工具确认的 `sent` 和 Worker 确认理解对应版本的 `ack`。Worker 进展及验收另行记录。预设的演练变更要注明由试跑负责人注入。

只有用户明确要求才能新增或解除对应暂停。按协调协议冻结匹配范围，继续无关工作。停止指令与只读状态核查始终允许，停止请求被接受后仍需核实实际停止状态。恢复前重查剩余暂停、最新需求、Worker、产物和证据。

## 回收与验收

Worker 使用 `progress`、`ready`、`blocked` 或 `failed` 回报。只有 Router 可以记录 `dropped`。`ready` 表示产物提交验收。验收单独使用 `passed`、`failed` 或 `unverified`，并绑定当前需求、上下文、分派、验收项和产物摘要。

Worker 报告 `ready` 后，Router 先核对当前分派与暂停范围，再对照当前版本验收产物。旧分派迟到回报只记历史。旧验收结果仅在验收项及证据未受影响、产物摘要一致并显式办理证据沿用后计入当前验收。失败交回适用分派修复，存在依赖则同步相关任务。

跨模块约定、安全或数据迁移、关键业务规则、需求中途变化，或实现者证据不足时，须由未参与实现的 Router 或其他 Worker 按原要求和冻结验收项独立复核。无法取得独立证据时保持 `unverified`。普通低风险改动由 Router 复跑即可。只有宿主提供只读隔离时才声明只读权限。

必要验收项全部通过才交付完成。缺少证据标为未验证，并继续获取可取得的证据。确实缺少外部条件时说明缺少什么、已做什么和剩余工作。试跑中可用旧版本产物验证新增标准确实能拦住过时结果。

替补产物只有在按协议完整确认目标写域已释放（含后台写入进程）且无适用暂停时才能集成，集成后重新验证。收工前确认当前需求版本、全部交付物、必要验收项、Worker 状态及尚存风险。只对用户真正请求的持久目标使用当前环境的 goal 工具。

最终向用户说明完成了哪些要求、产物位置、实际验证结果和未验证限制。模型、并发、研判次数按真实记录汇报。保持常规执行细节在运行记录中，向用户及时反馈结果、关键取舍与具体卡点。
