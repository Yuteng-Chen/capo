# 宿主运行策略

首次派工前检查当前宿主和实际调用入口，确认可用的派发、发消息、续投、列出状态、停止能力，以及模型覆盖、推理档位、上下文继承和并发限制。记录能力的观察来源。某入口列出的模型、另一入口的成功记录或默认配置都不足以确认当前入口实际生效的模型。

## 模型角色

| 角色 | 工作 | 宿主支持时的配置示例 |
| --- | --- | --- |
| `routine` | 常规调查、整理、检查和小改动 | Sol，`low` |
| `complex` | 复杂排查、实现和独立复核 | Sol，`xhigh` |
| `analyst` | 证据齐备后仍需深入判断的只读研判 | Astra，`high` |

按用户约束、当前入口支持与已知的实际模型选择角色配置，使用宿主真实标识和参数。宿主要求从空白上下文才能覆盖模型时，选择相应模式并传入完成任务所需的上下文。记录请求值、实际生效值及来源（显式、继承、回退）。入口仅确认接收请求时，按实际模型可确认程度记录，未知值写 `unknown`。模型或档位不可用时，在用户授权范围内选择符合角色和预算的可确认配置，或交 Router 串行执行。

## 高级研判预算

每轮默认额度为 0。增加额度需用户明确授权。每次开始一个 `analyst` Worker 轮次，或有效模型属于 Astra 的任何 Worker 轮次，消耗一次额度。同一轮次满足两项仍计一次。显式配置、继承、回退、应用恢复或对原 Worker 的唤醒均按实际生效值计。主会话的模型和已发生的主会话执行不计入 Worker 预算。

- 在任何可能启动新 Worker 轮次的调用前，核对适用暂停、写域、并发和模型预算，并预留可能消耗的额度。`spawn`、`followup`、宿主可能用来唤醒的 `send` 或恢复操作都纳入检查。只有宿主能力与当前状态确认消息仅投递给已经运行的轮次时，才无需为 `send` 额外预留。
- 调用是否会启动轮次未知时，按可能启动新轮次检查和预留。对角色、有效模型或回退路径无法排除高级研判消耗的调用，保守预留研判预算。零预算只允许能够确认属于 `routine` 或 `complex`、且有效模型及可能回退均为非 Astra 的新轮次。无法做到时由 Router 串行处理。存在实际有效模型未知或可能启动高级轮次的未决派发时，保留相应预留并报告实际消耗待确认，不宣称零 Astra。
- 确认高级轮次已启动后将预留转为已用。实际进入使用不同配置的轮次时按实际角色和有效模型结算，确认不占预算的预留可释放。确认未启动才释放因结果未知而保留的预留。不同轮次分别记账，即使属于同一 Worker。若实际配置违反预算，记录超额和原因，停止同类业务派发并核对宿主能力。
- 停止控制和只读状态核查无需通过业务派发预算或并发检查。优先使用不会起新轮次的停止能力。若唯一可用的停止投递可能唤醒 Worker，仅发送停工或交回指令，实际启动的轮次照实记账并注明控制例外。该例外不覆盖用户明确的模型禁令、费用硬限制或宿主权限限制；无法满足这些限制时不启动该轮次，继续冻结业务动作，报告实际停工尚未确认及可用的人工停止方式。

## 全树并发与派发

本 Skill 不设固定 Worker 数量上限。Router 根据可独立推进的任务、依赖、可写范围和宿主实际可用容量决定并发数量，不为占满槽位而拆单。用户明确设定并发值时，同时遵守该值与宿主限制；宿主槽位若包含 Router 或其他代理，须按宿主口径扣除占用，不能将总槽位直接当作可新增 Worker 数量。宿主上限未知时，先核查能力与现有占用，不将未知视为无限容量；无法确认还有容量时将新增派工排队，继续已确认可执行的工作。

Router 统一决定派工、持有槽位和记录状态，Worker 默认不递归派工。用户显式授权递归时，还须宿主支持，由 Router 对全树集中发放预留，子 Worker 仍适用相同预算和控制。继承用户上下文或隐式触发 Skill 本身不授予 Worker 派工权。

- 运行中的 Worker、启动结果未知的预留和停止结果未知的 Worker 均计槽。每个活跃 Worker 及其同一槽位上的未确认操作只计一次，尚未识别到 Worker 的启动尝试单独保留槽位。只在确认未启动、已空闲且无待启动轮次或已停止时释放槽位。释放槽位与交回写域分别核实。
- 每次业务派发先登记操作标识和预留，再调用工具。明确返回 `model_not_found` 且能确认请求在创建或唤醒任何 Worker 前被拒绝时，可释放预留，并在重新检查预算及宿主支持后做一次有依据的回退。授权拒绝遵守宿主限制。
- 超时、连接断开或返回缺少身份导致启动结果未知时，保留尝试记录和预留，先查宿主状态、已有任务和尝试标识，确认是否创建或唤醒了 Worker。找到已有执行则接管记录；能确认未启动才考虑重新派发。无法查清时保持未决，不直接重试同一工作。确认写域安全且不影响未知尝试时，继续独立工作。
