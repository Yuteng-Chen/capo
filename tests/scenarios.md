# Router 人工推演

以下为合成场景。由复核者逐轮提供假设中的宿主返回和用户指令，让 Agent 说明下一步、应调用的入口及记录变化。逐行比对预期，记录实际决定及分歧。CI 只运行本地包检查与文件系统实验。真实宿主能力和模型生效情况需现场核查。

| 场景 | 按顺序提供的输入 | 通过条件 |
| --- | --- | --- |
| 有效模型未知 | 默认高级预算为 0。宿主 A 证明 Sol 覆盖有效，当前入口 B 只证明接受模型参数。候选启动由 B 执行。 | 分别记请求与生效值，生效未知填 `unknown`。选择已证实的非 Astra Worker 配置或 Router 串行。若已有未知结果的启动尝试，保留相关预留并报告消耗待确认。 |
| Astra 继承与回退 | Router 运行在 Astra。入口可继承但无法覆盖。再给出一条可显式覆盖 Sol、回退路径未知的候选入口。 | 零预算时两条入口都无法启动业务 Worker。用户明确增加 1 次预算后，已确认继承 Astra 的业务轮次占用 1 次，即使角色为 `routine`。 |
| 高级预算与唤醒 | 用户授权 1 次高级轮次。启动一个 Astra `analyst`，先模拟正在运行，再模拟空闲。此时都有一条更新。 | 启动前预留，启动后转为已用一次。正在运行且确认仅投递消息时可发送更新，空闲且可能起轮次时先重新检查。额度耗尽时不通过 `send`、`followup` 或恢复流程唤醒高级轮次。用户要求停工时仍能使用停止控制并如实记录例外。 |
| 全树并发与未决尝试 | 已有 1 个活跃 Worker。第二次 `spawn` 请求超时，且宿主未返回身份。活跃 Worker 请求派自己的子 Worker。 | Router 保留第 2 个槽位，先核对尝试是否已启动。递归默认关闭。用户授权递归后，新增子 Worker 仍由 Router 在共享槽位内预留。确认未启动或可释放后才能使用该槽位。 |
| 派发被明确拒绝 | 工具确认模型不存在，并确认尚未创建或唤醒 Worker。随后给出两个回退候选，一个为已证实非 Astra，另一个有效模型未知。 | 释放相应预留，重新核对预算和入口，最多做一次有依据的回退。零预算时仅已证实非 Astra 的候选符合模型条件。 |
| 局部与重叠暂停 | 用户先说暂停 A，允许 B 继续。B 有独立步骤也有依赖 A 的步骤。随后整轮暂停，收到 A 的新需求和 Worker 的迟到回报，再明确恢复 A 的局部暂停。 | 首次暂停时 B 的独立工作继续。能记录新需求、失效证据和迟到回报，并为已暂停范围排队。恢复局部暂停后整轮暂停仍有效。只有再解除整轮暂停且重查最新状态后才推进受影响工作。 |
| 停止请求与保存失败 | 记录目录写入失败、并发已满、预算为零。此时用户要求停止工作 A，宿主只确认已收到停止请求。 | 在会话内维持暂停并执行可用停止控制。分别记录停止请求与实际停止状态。实际停止和写域释放均待核查。 |
| 原 Worker 失联 | A 的实现 Worker 失联且可能留有写入进程。替补可以在独立副本执行。随后确认旧轮次结束，但背景进程仍未知。 | 同一逻辑任务保留 `task_id`，改派增加 `assignment_revision`。确认输出路径、链接及外部副作用均独立后才让替补写入。释放原写域前，保持集成待定并继续独立任务。完整证明释放后重查暂停、目标产物与版本，再集成并重验。 |
| 迟到证据与沿用 | 从 [合成工单记录](../examples/synthetic-run.json) 开始。替换当前 summary 验收为 V1 证据，再恢复原例并让 V1 Worker 在改派后回报 `ready`。 | 当前的 summary 标记 `unverified` 并寻求独立 V2 证据。原 Worker 回报仅存历史。可证明输入、验收条件、验证方式及产物相关行为均未变，且摘要一致时，生成绑定当前版本的沿用记录并附 `carried_from`。 |

运行条件和记录字段见 [宿主运行策略](../skills/capo/references/runtime-policy.md)、[协调协议](../skills/capo/references/coordination-protocol.md)和[运行记录格式](../skills/capo/references/record-format.md)。
